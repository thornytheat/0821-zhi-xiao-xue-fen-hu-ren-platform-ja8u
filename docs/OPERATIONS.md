# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 逐个申请复核：可签发的申请先签发，仍有差异、冲突或无归属坏行的申请暂缓。
5. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。

## 复核口径

- 同一记录号指向两份申请，涉及的两份申请都暂缓。
- 坏行找不到所属申请（`case` 不在采信分组内），该批申请全部暂缓。
- 冲突记录的两份副本都隔离，所属申请暂缓；逐字重复的回放只计忽略行，不影响签发。
- 更正材料与签发同时提交时，新版材料已生效就拒绝按旧材料签发；补正后的申请在重新执行批次时重新核算。
